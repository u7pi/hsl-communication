# HslCommunication 开源版维护指南（v7.0.1 基线）

> 目标：在“最后公开开源版本”基础上，安全、可回滚地持续演进。

## 1. 维护原则

1. **先兼容后优化**：优先保证现网设备可用，再考虑重构。
2. **最小改动面**：协议层改动尽量局部化，不做跨协议大面积联动。
3. **可追溯**：每次改动都记录设备型号、地址区、现象、抓包/日志结论。
4. **可回滚**：所有协议行为变更均要可通过配置或分支快速回退。

## 2. 分支与发布策略（建议）

- `main`：稳定可发布分支，仅合并通过回归的变更。
- `develop`：日常集成分支。
- `feature/<protocol>-<topic>`：协议功能分支，例如 `feature/modbus-timeout-tuning`。
- `hotfix/<issue>`：线上故障快速修复。

发布建议：

- 每次发布打 tag：`v7.0.1-custom.<yyyymmdd>.<n>`。
- 每次发布附带“设备回归清单”与“已知风险”。

## 3. 改动优先级与边界

### 3.1 优先级

- P0：现场故障（连接中断、误写、数据错位）。
- P1：性能/稳定性（超时、重连、并发争用）。
- P2：可维护性（日志补充、文档、注释、示例）。

### 3.2 边界控制

- 避免在同一次 PR 同时修改：
  - `Core` 通信基类 + 多个协议目录。
- 优先采用“适配层”而非直接改动已有对外 API。
- 如需修改公共行为，先在 `TestProject` 补可复现实验。

## 4. 协议开发工作流（推荐）

1. **复现问题**：固定设备、寄存器、读写类型、频率、并发数。
2. **定位层级**：区分是链路问题（网络/串口）还是报文问题（协议编码）。
3. **加观测点**：在请求前后补充 trace 日志（耗时、重试、异常码）。
4. **最小补丁**：先实现最小修复版本。
5. **回归验证**：至少做“成功路径 + 异常路径 + 边界路径”。
6. **记录结论**：更新文档与变更日志。

## 5. 回归模板（可直接复制）

建议在每个协议 PR 描述中附上如下清单：

- 设备型号：
- 通信介质：TCP / 串口 / UDP
- 地址范围：
- 数据类型：Bool / Int16 / UInt16 / Int32 / Float / String
- 并发策略：单线程 / 多线程
- 超时设置：
- 验证项：
  - [ ] 连接建立与断开
  - [ ] 单点读写
  - [ ] 批量读写
  - [ ] 连续 30 分钟稳定性
  - [ ] 异常恢复（断网/断电/设备重启）
